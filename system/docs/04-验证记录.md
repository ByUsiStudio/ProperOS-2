# 验证记录（ARM64）

所有结论均来自真实构建与 QEMU 运行，不是纸面推演。测试宿主无 KVM，用 TCG 软件模拟，
因此比真机慢，但引导链、安装链、运行时行为与真机一致。

## 1. 环境

| 项 | 值 |
|---|---|
| 构建宿主 | Ubuntu 22.04 x86_64，5 vCPU / 8 GiB |
| 内核 | Linux 7.3.6 stable，交叉编译 `ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-` |
| 目标平台 | ARM64（aarch64），UEFI（AAVMF / EDK2 2024.02） |
| 运行环境 | QEMU `-M virt -cpu cortex-a72`，3 GiB，2 vCPU，virtio-blk / virtio-scsi / virtio-gpu / virtio-net / virtio-keyboard / virtio-tablet |
| 用户空间 | Debian 12 bookworm minbase + systemd 252（qemu-user-static 二阶段 debootstrap） |
| 屏幕 | 720×1280（竖屏手机，dn=2.0）与 1280×800（横屏，dn=2.2）两档 |

## 4. 过程中发现并修复的真实缺陷

只有真正跑起来才会暴露的问题，均已修复并回归。

### 4.1 引导与安装

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| ISO 不进 GRUB | 固件报 `failed to load Boot0001 ... Not Found` | El Torito 扇区计数只有 16 位，32 MiB 的 efiboot.img = 65536 扇区溢出为 0 | EFI 镜像改 16 MiB FAT16（32768 扇区），只保留单一 El Torito 条目 |
| 光驱无设备节点 | live 里没有 `/dev/sr0`，介质探测失败 | 内核没开 `SCSI_VIRTIO` / `BLK_DEV_SR` | 补齐两项重编内核 |
| 串口全空 | `console=ttyAMA0` 却没有任何输出 | 缺 `SERIAL_AMBA_PL011`，ttyAMA0 根本不存在 | 启用 PL011（含 console） |
| 无键盘 | QEMU 里按键无反应 | ARM virt 没有 PS/2，内核缺 `VIRTIO_INPUT` | 启用 `VIRTIO_INPUT`，启动命令加 `-device virtio-keyboard-pci` |
| 装完启动器被屏蔽 | 目标机 `properos-shell.service -> /dev/null` | squashfs 带着安装器为独占 tty1 做的 mask | live 改动移到 `installer/init` 写进 overlay 上层 |
| 装完进 emergency | 等 `dev-disk-by\x2dlabel-PROPEROS` 超时 | live 的 `/etc/fstab` 是目标机写法 | 安装器只从只读 squashfs 拷贝 |
| 启动日志有乱码 | 引导阶段中文变方块 | 引导阶段没有任何 CJK 字体 | ProLoader / StBoot / bootctl 输出改 ASCII |
| `Can't lookup blockdev` | 首启日志出现该行 | bootctl 无条件 mount `by-partlabel` 链接 | 先 `access()` 判断再挂载 |

### 4.2 图形层与桌面

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 720×1280 下字号只有 11–13px | 手机上字小到看不清 | 字号写成固定像素，没考虑 2 倍密度屏 | 引入 `dn = min(W,H)/360`，字号与间距全部按 `DP()` 换算 |
| 壁纸中间有横向硬边 | 屏幕中部出现明暗台阶 | 上半段用 `top→mid` 铺满全高，下半段又从 `mid` 起画 | 改成两段各画 `H/2`，接缝处同为 `mid` |
| 图标行距被拉得很散 | 10 个应用占不满一屏时，行距达 277 px | `cell_h = 可用高度 / 4`，把小数量内容强行摊开 | `cell_h` 固定 88 dp，网格按实际行数居中（上偏 38%） |
| 浮层打开时底层抢点击 | 快捷设置里点 WLAN 磁贴，结果打开了设置应用 | 桌面图标网格与磁贴的点击区重叠，两层都消费同一个 tap | `draw_home(int interactive)` / `draw_dock(int interactive)`，浮层打开时只绘制不消费 |
| 应用抽屉背景透出桌面图标 | 抽屉里能看到两层图标重影 | 面板用了 246 的半透明填充 | 改完全不透明，并在顶部加分割线 |
| 快捷设置铺满全屏却只有一小块内容 | 面板下方大片纯色空洞 | 面板高度写死 `H*0.66` | 按内容预算算面板高度，未覆盖区域用 120 透明度的黑色遮罩压暗 |
| 快捷设置收不起来 | 上滑没反应，只能点空白 | 只处理了「底部边缘上滑」手势，面板内部滑动被当成普通 swipe | `IN_SWIPE` 分支：QS 内上滑收起、抽屉内下滑关闭 |
| 应用内边缘返回失效 | 设置页左边缘内滑不退出 | `IN_EDGE_*` 分支写成「有输入焦点只清焦点，否则才退栈」，点过开关后第一次滑动被吞掉 | 改为无条件清焦点 + 退栈 |
| jspk 顶栏关闭按钮点不到 | 点右上角 × 无反应 | 命中区写成 `ui_hit(cx-22, 6, 48, H-12)`，把高度当宽度用 | 改成 `ui_hit(W-64, 0, 64, H)` |
| 从应用返回后图标残留按压高亮 | 回到桌面时某个图标背后多一块浅色圆角块 | 应用退出后 shell 用上一帧的 `u.down` 重绘了一帧 | 收到任何「抬手后」语义事件时先 `u.down = 0`，再分发 |

### 4.3 .jspk 运行时

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 中文全变 `ä¸æ` 乱码 | 所有中文标签显示为双重编码 | JSON 解析器把已是 UTF-8 的字节当码点又 `put_utf8()` 编了一遍 | 非转义字节直接透传 |
| 对象键名被值覆盖 | `{"title":"设置"}` 里键名丢失 | `jval_t` 的键名与字符串值共用 `str` 字段 | 新增独立 `char *key`，`json_get` 比对 `key` |
| DEFLATE 解压崩溃 | 打开压缩过的 `.jspk` 段错误 | `codes()` 传表时漏了符号表 | 签名改为 `codes(s, lencnt, lensym, distcnt, distsym)` |
| 计算器白底白字 | 数字按键看不见 | 磁贴按 `tint` 上色后没算前景对比度 | 按亮度选前景：`lum > 170` 用深色字 |
| 计算器表达式不显示 | 只有结果没有输入 | `tpl()` 只认内置键（time/date/battery…），不认应用状态变量 | `tpl()` else 分支遍历 `vars[]` 插值 |
| 开关圆点跑出轨道 | 小尺寸下圆点压在边框上 | `kx` 按固定 4 px 内边距算 | 按半径算：`kr = h/2 - 4dp`，`kx = on ? x+w-4dp-kr : x+4dp+kr` |
| 磁贴副标题贴边被裁 | 「2 个已启用」贴到卡片底边 | 标题/副标题用固定 `DP(19)`/`DP(10)` 定位，没考虑字号 | 改成 `sub_y = cell - 8dp - FS_TINY`，标题在其上方 |
| 计算器多出第二个除号 | 右下角出现 `/` 键 | JSON 里 20 个格子塞了 19 个有效键 + 1 个重复键 | 去掉重复键，给 `tiles` 加 `span` 支持让 `=` 跨两列 |
| 减号不显示 | 减号按键是空白 | `−`(U+2212) 不在字库图集里 | 改 ASCII `-` |
| 设置页开关与系统状态矛盾 | 桌面 Wi-Fi 开着，设置里显示关 | jspk 把 `wifi` 存在自己的 `state.conf`，与 `system.conf` 各记一份 | `is_sys_key()` 白名单，系统键统一读写 `system.conf`；退出应用后桌面重读配置 |
| 拨号盘顶部空一大块 | 号码框为空时只剩空白 | `{{number}}` 为空串，但字号仍是 32px | 新增 `empty` 属性：变量为空时显示占位文字并按正文字号渲染 |

### 4.4 测试方法学到的

| 现象 | 说明 |
|---|---|
| QEMU 断电导致 ESP 报 `fat_free` 损坏 | `VM_KEEP_DISK=1` 复用同一块盘、结束时直接 terminate，相当于拔电；FAT32 元数据未刷盘。后续测试每次从镜像重新 `qemu-img convert` 一份干净副本，并在结束前 `system_powerdown` |
| 串口 `run()` 里命令以 `&` 结尾 | 包装成 `printf ...; {cmd}; printf ...` 后变成 `... & ; printf`，bash 直接语法报错，命令根本没执行。后台命令要写成 `( cmd & ) ; true` |
| 抽屉里点设置的坐标 | 4 列网格 `cell_h=156`，第三行中心在 y≈385；按比例估算容易落到第 4 行空白区 |

## 5. 端到端结论

QEMU/ARM64 上完整走通：

```text
UEFI → GRUB → Linux 7.3.6 → initramfs → ProLoader（A/B 选择 + SHA-256 校验）
     → StBoot（只读根 + /data 叠加）→ systemd → properos-shell（Plasma Mobile 形态）
     → 手势（上滑抽屉 / 下拉快捷设置 / 边缘返回 / 长按菜单）
     → properos-app 解释执行 .jspk → 应用内滚动与开关 → 关闭回到桌面
```

并且从 ISO 完整走通一次「图形向导安装 → 重启 → 从设备启动 → 桌面可用」。

## 6. 已知限制

| 项 | 现状 | 处理方式 |
|---|---|---|
| Secure Boot | 引导器自签，无微软 UEFI CA 签名 | `properos-mok-enroll`：生成 MOK → `sbsign` 签 `BOOTAA64.EFI` → `mokutil --import` 登记，之后可重开 Secure Boot |
| 设备树 | 通用镜像面向 QEMU virt 与已跑 UEFI 的设备 | 构建时 `PROPEROS_DTB=board.dtb`，DTB 写进 `/dtb/board.dtb` 并由 GRUB `devicetree` 加载 |
| A/B 槽 | 安装器只填充 A 槽 | `properos-bootctl sync` 复制活动槽到另一槽并标记 good |
| 中文控制台 | 图形界面全中文，纯文本控制台 ASCII | 内核控制台字体上限 512 字形，放不下 CJK，无法真正解决 |
| ppkg 签名 | 默认校验 SHA-256 | `ppkg sign` 生成 `SIGNATURE`，公钥放 `/etc/properos/keys/ppkg.pub` |
| TCG 环境 | 无 KVM 时性能约 1/10 | 真机用 KVM；图形界面在 TCG 下仍可用，滑动动画会掉帧 |
