# ProperOS 2.5 Mobile · 架构与实现

本文描述 2.5 手机端各层的**实际实现**（不是设想），对应源码目录与可执行文件。

- 开发者：ByUsi Studio · 北啊呢
- 应用包名前缀：`miao.byusistudio.***`

---

## 1. 引导链

```text
UEFI 固件
  └─ ESP:/EFI/BOOT/BOOTAA64.EFI        GRUB 2.06（单文件，模块内嵌）
       └─ ESP:/slots/a/Image            Linux 7.3.6
            └─ ESP:/slots/a/initramfs.img
                 └─ /init = ProLoader（静态 C，PID 1）
                      ├─ 挂载 /proc /sys /dev /run
                      ├─ 解析内核参数 + ESP:/proloader/proloader.conf
                      ├─ A/B 槽选择（失败计数、自动回滚）
                      ├─ 校验 slots/<slot>/SHA256SUMS
                      ├─ 只读挂载 properos-system → /sysroot
                      └─ exec /sysroot/usr/lib/properos/stboot
                           └─ StBoot
                                ├─ 挂载 properos-data → /data
                                ├─ 首启播种 /etc /var /home /root
                                ├─ bind mount 可写层
                                └─ switch_root → systemd
```

### ProLoader（`src/proloader/proloader.c`）

| 能力 | 实现 |
|---|---|
| 设备发现 | 无 udev 环境，扫描 `/sys/class/block/*/uevent` 的 `PARTNAME/PARTUUID` |
| 配置 | `proloader.conf`：`slots` `default_slot` `max_tries` `verify` `splash_message` |
| 状态 | `slotstate`：`active` `a_tries` `b_tries` `a_good` `b_good` |
| 校验 | `SHA256SUMS` 中每个文件（内核、initramfs）逐项比对 |
| 回滚 | 当前槽失败次数 > `max_tries` 或校验失败 → 切到另一槽 |
| 诊断 | `proloader status` / `proloader verify a` |
| 失败处理 | 打印原因 → 10 秒内按回车进入 initramfs 救援 shell，否则重启 |

`a_tries` 在每次引导时 +1，用户态 `properos-bootctl mark-good`（首启由 `properos-firstboot.service` 调用）清零，实现“连续失败自动回滚”。

### StBoot（`src/stboot/stboot.c`）

- 系统分区**只读**挂载，可写状态全部落在 `/data`；
- 首启把系统种子 `/etc`、`/var`、`/home`、`/root` 复制到 `/data`，之后以 bind mount 叠加；
- 生成 `/data/etc/machine-id`；
- 无数据分区时降级：先 bind 原 `/etc` 到临时点，再用 tmpfs 覆盖并回填，保证仍可启动；
- 写入 `/run/properos/boot.status`（槽、时间、版本）后 `switch_root`。

这种设计使系统分区可以整体替换（A/B 升级、恢复出厂），用户数据独立保留。

## 2. 系统层

- **systemd**：服务编排、getty、网络（networkd + DHCP）、日志。
- **podman 4.3 rootful**：`overlay` 存储、`netavark` 网络、`cgroup v2`。
- **properd**（`src/properd/properd.c`）：移动端服务/会话管理器。

### properd

```text
/etc/properos/services/*.service
    Name / Exec / User / Restart
```

- 启动时拉起全部服务；`SIGCHLD` 回收并按退避（1s→30s）重启；
- Unix socket `/run/properd.sock`：`list`、`status|start|stop|restart|launch <name>`；
- 每 5 秒输出 `/run/properos/services.json` 供界面层读取；
- 应用生命周期：`launch <appid>` → 调用 `papp run`。

## 3. 应用层

### `.papp` 包格式

```text
manifest.conf       # id/name/version/entry/network/author/description
root/               # 应用文件树（入口通常为 /app/run.sh）
icon.png            # 可选
SHA256SUMS          # papp pack 自动生成
```

`papp install` 会校验包内 `SHA256SUMS`，安装到 `/data/apps/<id>/`，并保留旧版本用于回滚；卸载默认移入 `/data/.trash`。

### 沙箱运行

`papp run` 建立独立命名空间（mount/uts/ipc，可选 net/pid），构建新根：

```text
/            ← 应用 root（只读挂载系统目录 /usr /lib /bin /sbin /etc）
/data /home  ← 应用私有可写目录（uid 10000）
/proc /dev /tmp
```

随后 `no_new_privs`、清空 capability、切换到 uid 10000 执行入口。应用无法访问其他应用数据与系统可写路径。

### 包名规范

应用 ID 采用反向域名：`miao.byusistudio.<app>`。官方示例：

```conf
id=miao.byusistudio.hello
name=你好
version=1.0.0
entry=/app/run.sh
network=0
```

## 4. 系统包层（ppkg）

`.jspk` 格式：

```text
PKGINFO      name/version/arch/depends/description
FILES        payload 内每个文件的 SHA-256
payload/     安装文件树
SIGNATURE    可选，对 FILES 的 Ed25519 分离签名
scripts/     pre-install / post-install / pre-remove / post-remove
```

- 安装前校验依赖是否已安装、文件哈希、可选签名（`openssl dgst -verify`，公钥 `/etc/properos/keys/ppkg.pub`）；
- 数据库 `/var/lib/ppkg/db/<name>` 记录 PKGINFO、文件清单、安装时间；
- 卸载按清单删除文件并执行脚本。

## 5. 界面层

`properos-shell`：直接写 `/dev/fb0`（32/16bpp），不依赖 X/Wayland。

- 中文界面：构建期用 Noto Sans CJK 烘焙 215 个字形位图（`tools/gen_font.py`），零运行时字体依赖；
- 布局：状态栏（时间/电量）、大时钟、4 列应用网格、Toast、关于面板；
- 输入：`/dev/input/event*`，支持触摸（ABS_MT/BTN_TOUCH）与键盘方向键/回车；
- 内置应用：终端（切 tty1）、文件、设置（tty3）、关于；已安装 `.papp` 自动出现在桌面；
- 无 framebuffer 时自动退出（systemd 单元带 `ConditionPathExists=/dev/fb0`）。

服务单元：`properos-shell.service` 运行在 tty7，`getty@tty1` 保留 root 登录（留空密码时自动登录）。

## 6. 安全模型

| 层 | 措施 |
|---|---|
| 启动 | 内核/initramfs SHA-256 校验；A/B 回滚；系统分区只读 |
| 应用 | 命名空间隔离、uid 10000、无 capability、`no_new_privs`、默认无网络 |
| 系统包 | 文件哈希 + 可选签名 |
| 容器 | rootful podman，默认不暴露端口；不做 privileged 默认 |

## 7. 与原始架构的差异（必须说明）

- 原始 `system.myu` / `codeProcessor.mjava` 是裕语言脚本解释执行；2.5 用**原生二进制 + 应用包**替代，语义等价但不兼容原脚本语法。
- `ProLoader` 在原始项目里是切换 Activity 的类；2.5 是内核启动后的第一阶段，接管槽选择与校验。
- `ppkg` 原为计划中的包格式；2.5 给出可用的 `.jspk` 实现（哈希/签名/依赖/数据库）。
