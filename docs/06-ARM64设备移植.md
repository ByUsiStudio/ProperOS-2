# ARM64 设备移植指南

ProperOS 2.5 的 ARM64 镜像面向**使用 UEFI 固件**的设备（QEMU virt、树莓派 4 的 UEFI、postmarketOS 支持的部分手机、部分平板）。本文说明如何把它落到具体手机。

---

## 1. 判断设备是否可直接使用

需要满足：

1. SoC 有可用的 UEFI 固件（如 `lk2nd` + `uefi` 组合、厂商 UEFI）；
2. 该固件能识别 GPT 分区并加载 `\EFI\BOOT\BOOTAA64.EFI`；
3. 内核包含该 SoC 的 pinctrl / clock / regulator / 显示 / 触摸驱动。

三条都满足 → 直接 `dd` 镜像即可。

## 2. 替换设备树（DTB）

通用镜像的 GRUB 条目不带 DTB。设备专用构建：

```bash
# 在设备树源中编译
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- qcom/sdm845-oneplus-enchilada.dtb

# 放进 ESP 的 slots/a/
mcopy -i esp.img sdm845-oneplus-enchilada.dtb ::/slots/a/dtb
```

在 `grub.cfg` 的 `linux` 行追加：

```text
devicetree /slots/a/dtb
```

同时更新 `/slots/a/SHA256SUMS`（加入 dtb 后 ProLoader 会一并校验）：

```bash
cd slots/a && sha256sum Image initramfs.img dtb > SHA256SUMS
```

## 3. 内核驱动

当前镜像内核为**单文件、无模块**（`CONFIG_MODULES=n`）。手机常见需要补充的驱动：

| 类别 | 配置项 |
|---|---|
| 显示面板 | `DRM_PANEL_*`、`DRM_MSM`（高通）/ `DRM_MEDIATEK` |
| 触摸 | `TOUCHSCREEN_EDT_FT5X06`、`TOUCHSCREEN_GOODIX`、`TOUCHSCREEN_ATMEX_MXT` |
| 电源/充电 | `QCOM_SPMI_*`、`CHARGER_*`、`MFD_*` |
| 存储 | `MMC_SDHCI_OF_*`、`SCSI_UFS_*` |
| 无线 | `WLAN`、`CFG80211`、厂商 `*_WLAN` |

修改方式：

```bash
cd linux-7.3.6
./scripts/config --enable DRM_MSM --enable DRM_PANEL_...
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- olddefconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) Image
```

然后替换 `dist/kernel/Image-properos-2.5` 并重跑 `build/arch/arm64/40-image.sh`。

> 需要模块的设备，把 `--disable MODULES` 改为 `--enable MODULES`，并在 rootfs 中执行 `make modules_install`，同时保留 `depmod` 生成的 `modules.dep`。

## 4. 分区与烧写

| 分区 | 标签 | 内容 |
|---|---|---|
| 1 | `properos-esp` | FAT32：`EFI/BOOT/BOOTAA64.EFI`、`slots/a/*`、`proloader/*` |
| 2 | `properos-system` | ext4：根文件系统（只读挂载） |
| 3 | `properos-data` | ext4：`/data`（应用、用户数据、可写层） |

烧写到手机（fastboot 环境通常写到 `userdata` 或整盘）：

```bash
# 整盘（eMMC/SD）
xz -dc ProperOS-2.5-arm64.img.xz | sudo dd of=/dev/mmcblk0 bs=4M status=progress oflag=sync

# 或仅写 boot 分区（保留 Android 数据时）
fastboot flash boot boot.img
```

### 与 Android 分区共存

若设备已有 Android，可只替换 `boot` 分区，把内核 + initramfs 打包为 Android boot image：

```bash
# 需要 mkbootimg（android-sdk 或 pip install mkbootimg）
mkbootimg --kernel slots/a/Image --ramdisk slots/a/initramfs.img \
          --cmdline "console=ttyAMA0,115200 root=/dev/ram0" \
          --pagesize 4096 --header_version 2 -o boot.img
```

ProLoader 通过 `PARTNAME` 查找系统分区，若你的分区名不同，修改 `proloader.conf` 的 `system_partuuid`，或用内核参数：

```text
properos.system=/dev/block/by-name/properos-system
properos.esp=/dev/block/by-name/properos-esp
```

## 5. 首次启动检查清单

```bash
uname -m                      # aarch64
uname -r                      # 7.3.6
cat /proc/cmdline             # 应含 properos.slot=a
properos-bootctl status       # active=a, tries=0
ip -4 addr show               # 无线/有线是否拿到地址
ls /dev/fb0                   # 有显示驱动时存在
journalctl -b -p err          # 查看驱动报错
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| UEFI 不启动 | 固件不识别 `BOOTAA64.EFI` | 关闭 Secure Boot；确认 ESP 为 FAT32 且有 `EFI/BOOT/BOOTAA64.EFI` |
| 卡在 `properos login:` 但无显示 | 显示驱动缺失 | 补 `DRM_*`/panel 驱动，或用串口 |
| `两个槽均不可用` | SHA256SUMS 不匹配 | 重新生成清单；或 `proloader verify a` 查看具体文件 |
| 触摸无反应 | 触摸驱动/设备树不匹配 | 补 `TOUCHSCREEN_*`，确认 `/dev/input/event*` |
| 无 `/dev/fb0` | 无 DRM framebuffer | 启用 `DRM_FBDEV_EMULATION` 或使用 simple-framebuffer |
| 数据分区未挂载 | 标签不对 | `blkid` 检查 `properos-data`，或用 `properos.data=` 指定 |
