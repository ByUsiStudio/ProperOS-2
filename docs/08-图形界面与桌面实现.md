# ProperOS 25.0.0 Mobile · 图形界面与桌面环境实现

本文描述图形安装器（`properos-setup`）与桌面环境（`properos-shell`）的实现，
两者共用同一套自绘图形库，不依赖 X11、Wayland 或任何 GPU 用户态驱动。

- 开发者：ByUsi Studio · 北啊呢

---

## 1. 为什么自绘

系统原有的启动器已经直接写 `/dev/fb0`。安装器如果继续用 whiptail，会有三个无法回避的问题：

| 问题 | 具体表现 |
| --- | --- |
| 观感割裂 | 文本对话框与桌面完全是两种视觉语言 |
| 交互受限 | 触摸屏无法操作 whiptail，只能靠外接键盘 |
| 中文排版 | 依赖 console 字体，80×25 下大量文案被截断 |

因此把绘制、文本、输入、控件抽成公共层 `src/gfx/`，安装器与桌面复用同一套代码。
代价是需要自己实现抗锯齿圆角、图标与软键盘；收益是整套界面在任意分辨率下都一致，
且不引入任何图形栈依赖（静态链接后单文件 4.5 MB）。

## 2. 图形库分层

```text
src/gfx/
├── gfx.h / gfx.c     画布、SDF 抗锯齿、阴影、渐变、文本、图标
├── input.h / input.c evdev 抽象：触摸 / 数位板 / 鼠标 / 键盘
├── ui.h / ui.c       即时模式控件：按钮、列表、开关、滑块、输入框、进度、软键盘
└── font_atlas.h      由 tools/gen_font.py 生成的灰度字形图集
```

### 2.1 画布

`gfx_t` 持有一个 32 位后缓冲，所有绘制先落在内存，`gfx_flush()` 一次性写回
framebuffer（支持 32bpp 与 16bpp）。这样避免逐像素写显存带来的性能损失，
也让离屏渲染（`gfx_offscreen`）成为可能——开发时可以直接在主机上导出 BMP 检查版式，
不必每次都启动虚拟机。

### 2.2 抗锯齿圆角

圆角矩形用有符号距离场（SDF）计算覆盖率，而不是按像素硬裁：

```c
static inline float sd_round_box(float px, float py, float cx, float cy,
                                 float hw, float hh, float r)
{
    float qx = fabsf(px - cx) - (hw - r);
    float qy = fabsf(py - cy) - (hh - r);
    float ax = qx > 0.f ? qx : 0.f;
    float ay = qy > 0.f ? qy : 0.f;
    float m  = qx > qy ? qx : qy;
    if (m > 0.f) m = 0.f;
    return sqrtf(ax * ax + ay * ay) + m - r;
}
```

覆盖率 `cov = clamp(0.5 - d, 0, 1)`，边缘自然过渡。性能上做了取舍：
矩形中部直接整块填充，只对四个角做 SDF 采样，一个 300×400 的卡片约 1 ms。

描边（`gfx_round_outline`）用「外缘覆盖率减内缘覆盖率」得到环形区域，
避免了先填后挖的两次混合。

### 2.3 阴影

阴影不是多层偏移叠加，而是同一条 SDF 加高斯衰减：

```text
alpha = exp(-d² / 2σ²) × A     (d 为到圆角矩形的距离)
```

一次遍历即可，且形状与卡片完全一致，不会出现「方形阴影配圆角卡片」的错位。

### 2.4 文本

字形图集由 `tools/gen_font.py` 从 Noto Sans CJK 烘焙而来，**每像素 1 字节 alpha**（旧版是 1 bit）。
灰度带来的差别在放大时非常明显：1 bit 放大后是硬锯齿，8 bit 放大仍是柔和过渡。

字符集覆盖：

| 范围 | 数量 |
| --- | --- |
| ASCII 可打印字符 | 95 |
| GB2312 一级汉字 | 3755 |
| 中文标点（。，、；：？！《》「」等） | 30 |
| 界面符号（← → ✓ ● ■ ⚙ 等） | 40 |
| 合计 | 3920 |

字形表按码点排序，运行时二分查找。整个图集 3.7 MB，静态链接进二进制。

绘制时按行扫描 alpha 并混合，`scale` 支持整数倍放大（1× 正文、2× 标题）。
所有字形都在同一高度的画布上按字体自身的基线渲染，因此中英文混排、标点下沉
都能自然对齐——这一点在早期版本里做错过（字形被顶对齐，句号会跑到字头）。

### 2.5 图标

没有引入图标字体或位图资源，全部用几何图元绘制（线段 + 圆 + 圆角矩形），
统一线性风格（stroke，不填充），因此同一个图标在 20 px 与 100 px 下都清晰。
目前内置 50 余个：`phone`、`message`、`browser`、`camera`、`settings`、`files`、
`terminal`、`wifi`、`battery`、`bluetooth`、`shield`、`chip` 等。

## 3. 输入抽象

`input.c` 把三类设备归一成五种语义事件：

| 事件 | 触发条件 |
| --- | --- |
| `IN_TAP` | 按下并抬起，位移 < 36 px |
| `IN_LONG` | 按住超过 520 ms 且未移动 |
| `IN_SWIPE` | 抬起时位移 ≥ 36 px，携带 dx/dy |
| `IN_MOVE` | 按下状态下移动 |
| `IN_KEY` | 键盘按键 |

设备类型通过 `EVIOCGBIT` 探测：

- 有 `EV_ABS` + `BTN_TOUCH/BTN_LEFT` → 触摸屏或数位板，按 `EVIOCGABS` 的
  min/max 把原始坐标线性映射到屏幕像素；
- 有 `EV_REL` → 相对鼠标，累积坐标并 clamp 到屏幕内；
- 只有 `EV_KEY` → 纯键盘。

坐标映射这一步是必要的：QEMU 的 virtio-tablet 上报 0..32767，触摸屏常见
0..4095，不能直接当像素用。

## 4. 控件层

即时模式（immediate mode）：不保存控件树，每帧按数据重绘，控件函数返回
「本次是否被点击」。调用方用绝对坐标布局，适合固定版式的手机界面。

状态只保留指针位置、按下状态与一个待消费的点击：

```c
int ui_button(ui_t *u, int x, int y, int w, int h, const char *label, btn_kind_t kind);
```

常见的坑是「点击穿透」：模态层（控制中心、软键盘）展开时，下层的图标不应该响应。
`ui_t` 里用一个 `block_from_y` 解决——设定后，该 y 以下的点击一律不生效，
上层面板绘制前再把阈值清掉。

### 4.1 软键盘

安装器需要输入主机名与密码，真机没有物理键盘，所以实现了屏幕键盘：

- 三行 QWERTY + 一行功能键（123/ABC、空格、句点、完成）；
- 字母页与数字符号页切换；
- Shift 单击生效一次，输入后自动复位；
- 退格按 UTF-8 边界删除，不会切出半个汉字。

## 5. 图形安装器

`src/ui/installer.c`，六个页面：

```text
欢迎 → 选择磁盘 → 设备配置 → 确认 → 安装进度 → 完成
                                  ↘ 错误
```

### 5.1 与安装脚本的分工

界面只负责收集参数与展示进度，实际写入仍由 `installer/install.sh` 完成。
两者通过管道通信：

```c
argv = { "properos-install", "--disk", dev, "--hostname", name,
         "--password", pass, "--yes", "--progress" };
```

脚本在每个阶段输出一行：

```text
##P 35|正在复制系统文件
```

前端逐行解析，更新环形进度与当前步骤。脚本的普通输出（分区、格式化、
rsync 统计）全部重定向到 `/var/log/properos-install.log`，不会污染管道。

这种分工的好处是：无人值守安装（`--auto`）与文本兜底（whiptail 向导）仍然可用，
三条路径共用同一套写入逻辑，不会出现「图形能装、命令行装坏」的分裂。

### 5.2 磁盘枚举

读 `/sys/block/*`，按以下规则过滤：

- 排除 `loop` / `ram` / `zram` / `nbd` / `sr` / `fd` / `dm-` / `md` / `pmem`；
- 排除容量为 0 或小于 2 GB 的设备（U 盘、分区表残留、内存设备）；
- 显示容量与 `device/model`，可移动介质额外标注。

### 5.3 密码策略

默认允许留空。留空时：

- `passwd -d root` 清空密码；
- `pam_unix.so` 加 `nullok`；
- getty 自动登录（`/etc/systemd/system/getty@tty1.service.d/autologin.conf`）。

界面上的开关与输入框联动：打开「不设置 root 密码」后，密码输入框显示为
已禁用状态，避免用户以为输入没生效。

## 6. 桌面环境

> **本节已部分过时**：桌面在 2.5 开发后期重写为 Plasma Mobile 形态
> （顶部状态栏 + 分页图标网格 + 底部 Dock + 应用抽屉 + 快捷设置 + 长按菜单，
> 深色主题、密度无关布局），完整说明见 `docs/09-桌面与jspk应用.md`。
> 下面关于图形层能力（图标绘制、plink 入口、状态数据）的描述仍然有效，
> 布局参数与视觉基准以 docs/09 为准。

### 6.1 视觉基准（历史记录）

取自 ProperOS 2 原桌面的设计语言，但不复刻：

| 元素 | 原示例 | 本实现 |
| --- | --- | --- |
| 主色 | `#3E7BFF` | 沿用 |
| 顶部 | 55 dp 圆角卡片 + Toolbar | 圆角卡片承载时钟、日期、状态 |
| 图标 | GridView，75 dp 列宽 | 4 列等距，图标圆角 `size/4` |
| 图标下名称 | TextView，居中 | 居中，超宽省略 |
| 背景 | 纯白 | 三档浅色渐变，可切换 |

原示例只有一屏 GridView 与一个标题栏，其余能力（分页、控制中心、搜索、设置、
长按编辑）是本次新增的。

### 6.2 布局自适应（历史记录，现行算法见 docs/09）

`layout()` 根据屏幕尺寸计算所有关键尺寸，行数随可用高度伸缩：

```c
L.pad    = min(W, H) / 22;
L.cols   = 4;
L.icon   = min(cell_w * 58 / 100, 100);
rows     = clamp(avail_h / (icon + 50), 3, 5);
L.icon   = min(L.icon, cell_h - 56);   /* 保证名称不被下一行压住 */
```

- 720×1280 → 5 行 × 4 列 = 20 个/页
- 1080×1920 → 5 行 × 4 列，图标 100 px
- 1280×800（横屏）→ 3 行 × 4 列 = 12 个/页

### 6.3 交互

| 操作 | 行为 |
| --- | --- |
| 点击图标 | 图标放大 + 整屏淡出 300 ms，随后启动应用 |
| 长按图标 | 进入编辑模式：图标抖动，左上角出现移除按钮 |
| 左右滑动 | 切换桌面页 |
| 顶部下拉 | 展开控制中心（时间、电量、四个快捷开关、亮度滑块） |
| 上滑 | 打开搜索 |
| 点搜索条 | 搜索页，按名称/包名过滤，可调软键盘 |
| 返回键 / Esc | 逐层退出（搜索 → 桌面 → 收起面板 → 退出编辑） |

### 6.4 应用入口：.plink

桌面图标来源于快捷方式文件，而不是直接扫安装目录。这是为了兼容原系统的语义：
ProperOS 2 的桌面就是 `home/Desktop/*.plink`，删掉 plink 等于从桌面移除，
应用本体仍在。

查找顺序：

1. `/data/home/Desktop/*.plink` —— 用户桌面；
2. `/usr/share/properos/desktop/*.plink` —— 系统预置；
3. `/data/apps/*/manifest.conf` —— 没有快捷方式的已安装应用（兜底）；
4. 内置系统应用（电话、信息、浏览器……），未安装时点击提示「尚未安装」。

`.plink` 的解析用了一个 60 行的宽松 JSON 取值器：同时接受 `"key": "value"` 与
hjson 风格的 `key: "value"`，因为原系统的 `MainIndex.json` 并不总是严格 JSON。

字段映射：

| 字段 | 用途 |
| --- | --- |
| `name` | 图标下方名称 |
| `package` | 启动时传给 `papp run` |
| `icon` | 图标 id（`phone`、`browser`…），缺省按包名哈希取色 + `store` |

启动命令：

```sh
setsid /usr/bin/papp run '<package>' >>/var/log/papp.log 2>&1 &
```

沙箱、权限、只读系统层全部由 `papp` 负责，桌面不参与隔离逻辑。

### 6.5 状态数据

| 数据 | 来源 |
| --- | --- |
| 电量 | `/sys/class/power_supply/*/capacity` |
| Wi-Fi | `/sys/class/net/wl*/operstate` |
| 时间 | `localtime()`，每分钟刷新一次 |

没有电池或无线网卡时对应元素不显示，不会出现「0%」之类的假数据。

## 7. 开发方式

界面不依赖虚拟机调试：

```sh
# 渲染桌面到 BMP
src/build/arm64/properos-shell --render 720x1280 /tmp/home.bmp

# 渲染安装器某一页（0 欢迎 / 1 选盘 / 2 配置 / 3 确认 / 4 进度 / 5 完成）
src/build/arm64/properos-setup --render 720x1280 /tmp/page.bmp 1
```

`--render` 走离屏画布，不需要 framebuffer 与输入设备，主机上直接跑。
版式调整在几秒内就能看到结果，比每次重启虚拟机快一个数量级。

## 8. 已知限制

| 限制 | 说明 |
| --- | --- |
| 无硬件加速 | 纯 CPU 光栅化，720p 整屏重绘约 25-40 ms（A53 级），只在事件时重绘 |
| 无窗口系统 | 应用全屏运行，桌面只在应用退出后可见 |
| 无中文输入法 | 软键盘仅 ASCII，主机名与密码够用；中文搜索依赖物理键盘 |
| 无图标资源 | 图标是矢量线稿，第三方应用只能从内置图标里选，或用哈希色块 + 首字母 |

这些限制都不影响安装与日常启动应用，属于后续迭代项。
