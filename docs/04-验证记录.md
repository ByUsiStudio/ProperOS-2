# 验证记录（ARM64）

所有结论均来自真实构建与 QEMU 运行，不是纸面推演。测试宿主无 KVM，用 TCG 软件模拟，
因此比真机慢，但引导链、安装链、运行时行为与真机一致。

## 1. 环境

| 项 | 值 |
|---|---|
| 构建宿主 | Ubuntu 22.04 x86_64，5 vCPU / 8 GiB |
| 内核 | Linux 7.3.6 stable，交叉编译 `ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-` |
| 目标平台 | ARM64（aarch64），UEFI（AAVMF / EDK2 2024.02） |
| 运行环境 | QEMU `-M virt -cpu cortex-a72`，2 GiB，2 vCPU，virtio-blk / virtio-scsi / virtio-gpu / virtio-net / virtio-keyboard |
| 用户空间 | Debian 12 bookworm minbase + systemd 252（qemu-user-static 二阶段 debootstrap） |

## 3. 端到端结论

QEMU/ARM64 上完整走通：

```text
UEFI → GRUB → Linux 7.3.6 → initramfs → ProLoader（A/B 选择 + SHA-256 校验）
     → StBoot（只读根 + /data 叠加）→ systemd → 移动端启动器
```

并且从 ISO 完整走通一次「向导安装 → 重启 → 从设备启动 → 启动器可用」。

## 4. 过程中发现并修复的真实缺陷

只有真正跑起来才会暴露的问题，均已修复并回归：

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| ISO 不进 GRUB | 固件报 `failed to load Boot0001 ... Not Found` | El Torito 扇区计数只有 16 位，32 MiB 的 efiboot.img = 65536 扇区溢出为 0 | EFI 镜像改 16 MiB FAT16（32768 扇区），只保留单一 El Torito 条目 |
| 光驱无设备节点 | live 里没有 `/dev/sr0`，介质探测失败 | 内核没开 `SCSI_VIRTIO` / `BLK_DEV_SR` | 补齐两项重编内核 |
| 串口全空 | `console=ttyAMA0` 却没有任何输出 | 缺 `SERIAL_AMBA_PL011`，ttyAMA0 根本不存在 | 启用 PL011（含 console） |
| 无键盘 | QEMU 里按键无反应，向导走不下去 | ARM virt 没有 PS/2，内核缺 `VIRTIO_INPUT` | 启用 `VIRTIO_INPUT`，启动命令加 `-device virtio-keyboard-pci` |
| 边框乱码 | whiptail 边框显示 `âöé`，中文变方块 | 控制台默认 8x16 且无 Unicode 表，ncurses 输出 UTF-8 制表符 | 装 16x32 VGA 布局字体（`Lat15-VGA32x16`），安装器 locale 固定为 `C` |
| 对话框缩在角落 | 输入框只画出底部一行 | 用 `$( )` 取返回值时 whiptail 的 stdout 变成管道，界面画不出来 | `ui_input`/`ui_password` 用 `3>&1 1>&2 2>&3` 做 fd 交换 |
| 进度条被糊掉 | 安装日志文字压在进度框上 | 进度阶段普通输出仍写 tty | `gauge_open` 后把 stdout 改道日志，保留 fd 9 供失败弹窗 |
| 进度始终 0% | 百分比不动 | `--gauge` 只吃百分比行，多发的空行被当成非法输入丢弃 | 每行只发数字，说明文字用固定文案 |
| 装完启动器被屏蔽 | 目标机 `properos-shell.service -> /dev/null` | squashfs 本身就是「live 版」，带着安装器为独占 tty1 做的 mask | live 改动全部移到 `installer/init` 写进 overlay 上层，squashfs 保持纯净 |
| 装完进 emergency | 等 `dev-disk-by\x2dlabel-PROPEROS` 超时 | live 的 `/etc/fstab` 是目标机写法 | 安装器只从只读 squashfs 拷贝（`/media/live-root`，兜底自己挂 loop） |
| 目标机串口 getty 失败 | `dev-ttyS0.device not found` | ARM64 上不该启用 ttyS0 | 按架构只启用 ttyAMA0 |
| 启动日志有乱码 | 引导阶段中文变方块 | 引导阶段没有任何 CJK 字体 | ProLoader / StBoot / bootctl 输出改 ASCII |
| 启动器不可见 | 启动器在跑但屏幕是文本 | 前台 VT 停在 tty1，被 getty 重绘覆盖 | `ExecStartPre` 执行 `chvt 7`，退出时回 `chvt 1` |
| `Can't lookup blockdev` | 首启日志出现该行 | bootctl 无条件 mount `by-partlabel` 链接 | 先 `access()` 判断再挂载 |
| 迁移挂载失败 | 首启 `failed to migrate dev/run` | `MS_MOVE` 用了相对路径，CWD 变化后指向普通目录 | 改绝对路径，并在移动前 `MS_REC\|MS_PRIVATE` |

## 5. 已知限制

- **Secure Boot 未签名**：需在固件中关闭 Secure Boot，或用 MOK 自行登记密钥。
- **文本控制台无中文字形**：安装器界面为纯 ASCII（与 Debian Installer 一致）；装好后的
  中文界面由帧缓冲启动器自带的 CJK 字库渲染。控制台可用 `properos-tty-console` 换字体。
- **字体栅格**：16x32 字体把 1280x800 排成 80x25；其他分辨率按字体尺寸自动重排，
  极低分辨率（<640x480）下对话框可能超出屏幕。
- **只读根**：`/` 只读，`/etc`、`/var`、`/home`、`/root` 由 StBoot 从 `/data` 叠加写入。
  临时改系统文件需先 `mount -o remount,rw /`（不建议，会让 A/B 校验失效）。
- **A/B 槽**：安装器只填充槽 A；槽 B 需要 `properos-bootctl` 配合后续 OTA 填充。
- **TCG 环境**：容器网络与 overlay 性能不代表真机；真机应使用 KVM。
- **`papp`/`ppkg` 输出为中文**：它们在启动器终端里运行（有 CJK 字库），
  在纯文本控制台上会显示为方块。
